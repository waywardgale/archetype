# Implementation status

The accepted design remains the v1 release contract. This page describes the code currently present, not a change to that contract. The current jar is an implementation milestone and is not v1 complete.

| Module | Working in the current build | Still required for v1 |
| --- | --- | --- |

All 16 scenarios in [ability-coverage.md](ability-coverage.md) remain release gates. Deterministic runtime tests establish advancing chain selection, falloff, revisiting policy, exhaustion, obstruction, attribution, and cancellation. Area/status tests establish independent overlapping membership buffs, periodic cadence, both stack-duration modes, numeric composition, callback ordering, source-filtered removal, and owned-work cleanup. Complete targeting feedback and running-world evidence remain absent, so no complete release scenario is claimed. No enabled class content ships in the mod; the test resources include an isolated conformance class.

## Verification on 2026-09-29

- `GRADLE_USER_HOME="$PWD/.gradle-user-home" ./gradlew test build validatePacks exportCatalog --offline -Ppacks=src/test/resources/packs/spatial` passes on JDK 25. There are 69 passing tests and no failures, errors, or skips. Jar inspection found no YAML fixture content.
- The offline validator accepts the nonempty fixture pack with one class, six named abilities and grants, one resource, one area, and two statuses. Catalog export writes parseable JSON with resolved internal references, the supported status tags and presence condition, and all registered effect types including `dispel`. The cleanse fixture converts the actual removed stack count into healing. This is structural editor assistance, not a replacement for semantic compilation or world checks.
- A Fabric 26.2 development server loaded the mod and dependencies, then stopped at the Minecraft EULA gate before world startup. Gameplay and client rendering have not been exercised in a running world.
- The pure tests cover the original resource/cooldown/save behavior plus all seven combat shapes, frame orientation, chains, isolated invocation bindings, target loss, moving and overlapping area memberships, expiry ordering, long-lived pulse budgets, death/logout/class-switch/dimension/unload/shutdown/reload cleanup, queued area/status dependencies, grounded placement, bounded overloads, overheal, namespaced built-ins, and a registered extension using the shared compiler/runtime contracts. Status regressions cover source refresh and cadence, independent owners and application identities, shared/per-stack duration and caps, lifecycle callbacks, speed composition, membership-owned descendants, prepayment capacity checks, refreshes at recipient capacity, and bounded dependency-graph estimates.
- Fourteen dispel regressions cover intersecting filters, source isolation across grants and owners, removal counts and ordering, live presence reads, self-removal, descendant cleanup, membership suppression and reentry, bonus recomposition, freed capacity, target loss and obstruction, read-only reload dependencies, reference-before-creation traversal, prepayment work limits, and located validation failures.
- Native API compatibility was checked by compilation and inspection of the cached 26.2 binaries, including transient attribute modifier operations. Spatial gameplay, native ray/shape behavior, movement speed bonuses, and live client input still need running-world verification. The earlier server startup attempt has not been repeated.
