# Implementation status

The accepted design remains the v1 release contract. This page describes the code currently present, not a change to that contract. The current jar is an implementation milestone and is not v1 complete.

| Module | Working in the current build | Still required for v1 |
| --- | --- | --- |
| Definitions | Strict captured YAML input; pack dependencies and IDs; `resource`, `ability`, `class`, and `area`; class grants by reference or inline; effect registrations shared by parsing/execution/schema export; bounded arithmetic and result availability; typed combat shapes and bounded living-entity selectors; reference and area-cycle checks; located errors | The remaining definition kinds; parameters; richer conditions and selectors; migrations; full registration contracts for conditions/selectors/events; the full mechanic catalog |
| Runtime | Server-owned class selection, resource costs and regeneration, cooldowns, actual damage/heal/overheal results, delayed/repeated/branched effects, private selection/chain bindings, bounded advancing chains, fixed and attached finite areas with enter/periodic/exit/expiry, membership-owned continuations, fresh controller pulse budgets, source cancellation and area-dependency reload reconciliation | Activation modes beyond activated; charges, statuses and membership buffs, events/reactions, maintained areas and event handles, named timers, empowerments, progression, summon state, terrain ownership, and the rest of the accepted composition contracts |
| Minecraft integration | Native healing and damage against living entities, damage registry checks including area bodies, bounded native target queries, server entity aim and ground raycasts, obstruction checks that avoid chunk requests, player save files, automatic whole-set reload, client-install check | Projectile and summon adapters, terrain journal and recovery, full combat event phases, richer targeting/native attribution, running-world integration evidence |
| Client | Class cycling, eight remappable grant keys, simple HUD, versioned state sync | Class/talent screens, configurable HUD position/scale, declared media, target previews, summon orders, ability pages, full slot binding |
| Authoring | Offline `validatePacks` using the runtime compiler; `exportCatalog` for supported editor structure and registered effect reference; optional spatial fixture pack and [authoring guide](spatial-authoring.md); bounded runtime failure diagnostics | Complete v1 schemas/catalog, checked examples for every mechanic, effective-definition inspector and event traces |

All 16 scenarios in [ability-coverage.md](ability-coverage.md) remain release gates. Deterministic runtime tests now establish advancing chain selection, falloff, revisiting policy, exhaustion, obstruction, attribution, and cancellation. Area tests establish membership transitions and owned delayed-work cleanup, including overlapping areas and expiry ordering. Membership buffs, complete targeting feedback, and running-world evidence remain absent, so no complete release scenario is claimed. No enabled class content ships in the mod; the test resources include an isolated conformance class.

## Verification on 2026-09-27

- `GRADLE_USER_HOME="$PWD/.gradle-user-home" ./gradlew test build validatePacks exportCatalog --offline -Ppacks=src/test/resources/packs/spatial` passes on JDK 25. There are 34 passing tests and no failures or errors.
- The offline validator accepts the nonempty fixture pack with one class, four named abilities and grants, one resource, and one area. Catalog export writes parseable JSON with resolved internal references and all registered effect types. This is structural editor assistance, not a replacement for semantic compilation or world checks.
- A Fabric 26.2 development server loaded the mod and dependencies, then stopped at the Minecraft EULA gate before world startup. Gameplay and client rendering have not been exercised in a running world.
- The pure tests cover the original resource/cooldown/save behavior plus all seven combat shapes, frame orientation, chains, isolated invocation bindings, target loss, moving and overlapping area memberships, expiry ordering, long-lived pulse budgets, death/logout/class-switch/unload/reload cleanup, queued area dependencies, grounded placement, bounded overloads, overheal, namespaced built-ins, and a registered extension using the shared compiler/runtime contracts.
- Native API compatibility was checked by compilation and inspection of the cached 26.2 binaries. Spatial gameplay, native ray/shape behavior, and live client input still need running-world verification. The earlier server startup attempt has not been repeated.
